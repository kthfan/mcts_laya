Laya + MCTS：以 AlphaZero 式自我對弈強化文字決策模型

技術報告　｜　涵蓋範圍：專案開始至第二輪 GPU 消融實驗與推論速度測試（2026-10-08）　｜　來源：docs/project_report.md

本研究以非自回歸決策模型 Laya 同時擔任 AlphaZero 架構中的 policy 與 value 網路，搭配 PUCT 蒙地卡羅樹搜尋，在文字環境上進行 Expert Iteration。在 TextWorld 中僅提供最終目標、需自行探索的關卡上，self-play 相對於「僅以 teacher 資料重複訓練」的對照組帶來穩定增益（成對差距：L2-goal +0.123 ± 0.049，L3-goal +0.227 ± 0.061；15 組同 seed 比較全數為正），且任務越難增益越大。增益主要來自價值網路：在 L3-goal，搜尋帶來的成功率增量於對照組由 0.14 縮至 0.06，於 self-play 組則擴大至 0.28。目標逐步給定的關卡（L1、L2）與料理關卡 C1 在 warm start 後已接近理論最佳，self-play 無可測增益。推論成本方面，PUCT16 每步約 206 ms，為 greedy 的 15.6 倍；模擬次數增為 64 次時每步僅增加約 20%，時間主要耗於環境而非模型。

1背景

1.1AlphaZero 與 Expert Iteration

AlphaZero 由兩個相互強化的元件組成。神經網路對局面 s 輸出 policy p(a|s)（各合法動作的先驗機率）與 value v(s) ∈ [−1, 1]（局面最終結果的估計）；MCTS 以網路輸出引導前瞻搜尋，產生優於網路本身的決策。訓練迴圈為：以「網路 + 搜尋」進行 self-play；以搜尋的拜訪分佈作為 policy 目標、以對局結果作為 value 目標訓練網路；網路改進後搜尋隨之改進。此「搜尋為教師、網路為學生」的框架即 Expert Iteration。

1.2Laya

Laya（Convai Innovations）為非自回歸決策模型：輸入「情境 + 問題 + 選項」，以單次前向計算輸出各選項機率。本研究使用 laya-multilingual（644 MB，多語 BERT 類編碼器），可於 CPU 執行。使用兩種題型：

  • choice（多選一）作為 policy：選項即合法動作。
  • noul（是 / 否）作為 value：「此局面能否成功」，V = 2·P(是) − 1。

各題型具溫度參數，用於機率校準。

1.3任務選擇

棋類狀態不適合以文字表達，因此選擇狀態本身為文字、可模擬、可自動判定成敗的任務：管線驗證階段使用 Countdown 與一元一次方程逐步化簡；主實驗使用 TextWorld（可控制房間數、物件數與任務步數的文字冒險遊戲產生器）；後續規劃 ALFWorld。

2系統架構

2.1整體迴圈

0. 基準評估：不使用 Laya 的搜尋（均勻先驗、隨機 rollout）
1. 初始評估：未微調的 Laya
2. Warm start：teacher 產生示範資料 → 訓練 Laya
3. 評估 → gate 記錄參考分數
4. 重複 N 輪：
   a. Self-play：Laya + MCTS 進行 64 局，記錄每步搜尋結果
   b. 每步轉為訓練樣本（policy 目標、value 目標）存入 replay buffer
   c. 以 replay buffer 訓練 Laya，校準溫度
   d. Gate：於驗證集評分；退步超過容許值即還原上一版權重
   e. 於測試集評估保留的權重
輸出：metrics.jsonl、summary.md、checkpoint

各元件（環境、評估器、搜尋、teacher、self-play、訓練器）透過註冊表以名稱組裝，替換環境或搜尋法僅需修改設定檔。

2.2環境介面

搜尋需自同一局面展開多個分支，因此狀態設計為不可變：step(state, action) 回傳新狀態，原狀態不變。資料分為 train、val、test 三組，TextWorld 以互不重疊的 seed 範圍產生：

切分遊戲數seed 範圍用途
train1500–149teacher 示範、self-play
val402,000,000–2,000,039gate 決策
test1001,000,000–1,000,099報告分數

2.3Laya 作為 policy / value 網路

每個局面轉為兩個共用狀態文字的 Laya 問題。policy 問題為「Which command brings you closest to completing the goal?」，選項為合法指令；value 問題為「Will the goal be completed within the remaining steps?」。實作要點：

  • Laya 內建批次 API 要求同批問題相同，而搜尋樹各葉節點選項不同；因此自行組合 token 序列，將多個葉節點合併為一批。
  • 依序列長度排序後分批，避免短的 value 列被補齊至長的 policy 列（Countdown 吞吐量由 1.6 提升至 4.1 rows/s）。
  • 以快取避免重複評估同一局面；模型更新後清空快取。

2.4搜尋：PUCT

score(a) = Q(a) + c_puct · P(a) · √N(s) / (1 + N(a))

葉節點以 Laya 估計 prior 與 value，value 沿路徑回傳更新 Q。根節點的拜訪次數分佈即為決策與 policy 訓練目標。設定如下：

2.5Self-play 與訓練目標

目標內容說明
Policy根節點拜訪分佈，經銳化（溫度 0.25）16 次模擬之分佈過於平坦，未銳化會稀釋 warm start 學得的偏好
Value該局最終 reward映射至 [−1, 1]

2.6Reward 設計

R = 0.5 + 0.5 · 0.9n（成功，n 為步數）；R = 0（失敗）

成功下限 0.5 確保「解出」恆明顯優於「未解出」；隨步數衰減以鼓勵效率。初始版本僅使用 0.9n，步數多時 reward 趨近 0、與失敗難以區分，導致價值網路傾向拖延。參考值：3 步 0.864、5 步 0.795、8 步 0.715。

2.7訓練器

  • 損失為 soft cross-entropy：policy 目標為拜訪分佈，value 目標為 [1 − p, p]。
  • 訓練時隨機打亂選項順序，避免位置偏差。
  • 凍結 token embedding（25.6 萬字詞表約占 60% 參數），並使用 gradient checkpointing。
  • 每輪保留 10%（上限 400 筆）資料不訓練，用於溫度校準。
  • CUDA 上使用混合精度：Ampere 以上 bf16；T4 / V100 使用 fp16 與 loss scaling。

2.8Gate 與評估設計

借自 AlphaGo Zero：每輪訓練後以驗證集評分，PUCT16 reward 低於歷史最佳逾 0.02 即還原上一版權重。評估設計歷經一次修正：

2.9平行對局架構

單局循序執行時 GPU 使用率僅 0–1%：TextWorld 每展開一個節點需重播歷史（約 50 ms，單核），而 GPU 處理一批僅需數毫秒。改採 AlphaZero 式架構：多個 actor 程序各自持有環境、搜尋樹並負責 token 化（每局面約 1.4 ms），將葉節點請求送至持有 GPU 模型的主程序合併批次推論。actor 數預設為 CPU 核心數 − 1（上限 32），每局獨立亂數種子，結果與排程無關。每個 actor 設記憶體上限 16 GB、每局時間上限 30 分鐘，超出即記為失敗並替換 actor。實測基準評估加速 4.6 倍，整體實驗由 72 分鐘降至 41 分鐘。

3任務

3.1管線驗證任務

  • Countdown：每步選兩數做四則運算，最終湊出目標數。reward 為是否成功；teacher 為窮舉搜尋。
  • 一元一次方程：如 5 = (x+3)/3 + (x+3)/2，每步選擇一個代數改寫，化為 x = c 即成功，以 SymPy 驗證。reward = 0.5 + 0.5·0.9n；teacher 為廣度優先搜尋（最短步數）。

Teacher：取自 TextWorld 依任務進度提供的最佳剩餘指令（policy_commands），並以 30% 機率隨機動作（explore: 0.3），使示範涵蓋偏離最佳路線的狀態。料理關卡的 teacher 先讀食譜。

實作：狀態以「遊戲 + 動作歷史」表示，取得觀察時重置並重播歷史（重置約 5 ms、每步約 7 ms），因 copy() 需 52 ms 且直接還原模擬器狀態會使任務追蹤不同步。每個遊戲保留至多 4 個引擎，並挑選已位於請求歷史前綴上的引擎續行；觀察以（遊戲, 歷史）快取。引擎時間因此減少約 30%，結果不變。

4實驗與結果

指標與統計

  • PUCT16 reward：Laya + 16 次模擬 PUCT 於評估遊戲之平均 reward（主要指標）。
  • 成功率；平均步數（含失敗局；L 關卡無失敗條件，失敗必走至上限：L1 10、L2 15、L2-goal 20、L3-goal 30）；成功局平均步數（僅計解出的局）。舊紀錄的成功局平均步數以（平均步數 − (1 − 成功率) × 上限）÷ 成功率精確換算。
  • Greedy：不搜尋，直接取 Laya 最高機率動作，反映網路本身能力。
  • 基準：uniform-puct16（均勻先驗、value 0）；rollout-puct16（隨機 rollout 估值）。
  • 雜訊：40 局 reward 不確定性約 ±0.03–0.05；100 局約 ±0.02–0.03。± 為跨 seed 標準差；成對差距為同 seed 相減後平均，以抵消 warm start 之 seed 差異。

5結論

  1. Laya + MCTS 的 AlphaZero 式迴圈於文字任務有效。在需探索的 TextWorld 關卡上，self-play 帶來明確且可重現的增益，難度越高增益越大；在模仿 teacher 即達最優的關卡（L1、L2、C1）上無差異。
  2. 增益主要來自價值網路。Teacher 示範僅能提供最佳路線，無法提供局面優劣的訊號；self-play 補足此訊號，使搜尋發揮作用，與 AlphaZero「搜尋品質取決於價值估計」的設計一致。
  3. 簡單設定即足夠。目前無進階變體優於「成功局搜尋分佈 + 銳化 + gate」。
  4. 搜尋成本可接受。L2-goal 上每步約 0.2 秒；模擬 ×4 每步僅 +20%，時間主要耗於環境。
  5. 限制。Self-play 於 1–2 輪後飽和；除 L3-goal 外各關卡已無比較空間；gate 驗證集僅 40 局，雜訊偏大。

7後續工作

  1. 評估時增加模擬次數：以 16 / 32 / 64 / 128 次模擬評估已訓練模型，檢驗搜尋可擴展性，並判斷 L3-goal 的飽和源於網路或搜尋預算。§4.7 已有初步跡象（L2-goal PUCT64 較 PUCT16 高 0.045，每步僅 +20%）。下一步於 L3-goal、100 局測試集、3 個 seed 確認，並比較 T-teacher-only 與 control：若僅 control 隨搜尋增加而提升，可更直接證明 self-play 改善的是價值網路。
  2. 確認機制：於 L3-goal 執行 B-value-only；若其與 control 相當，即確認 self-play 的貢獻來自價值網路。
  3. 更難的任務：C2（多食材、多房間料理），或 ALFWorld（環境、teacher 與設定已完成，待 GPU 實驗）。
  4. 延續 self-play 的增益：擴大驗證集以降低 gate 雜訊、增加每輪局數、逐步降低 teacher 資料比重。
